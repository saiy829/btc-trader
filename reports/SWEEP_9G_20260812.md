## 二、实现要点与实测依据

任务卡要求「禁止凭记忆写」。以下每项都有反射/实测来源。

### 2.1 反射确认的 API 签名

用 `AssemblyLoadContext` 从 ATAS 安装目录解析依赖后反射 `ATAS.Indicators.dll`：

```
AddAlert(String soundFile, String message)                       <- 采用（两参数版）
AddAlert(String soundFile, String instrument, String message, Color, Color)
IChartContainer.GetYByPrice(Decimal price, Boolean isStartOfPriceLevel)
IChartContainer.GetXByBar(Int32 bar, Boolean isStartOfBar)
IndicatorCandle: Open High Low Close Volume Bid Ask Delta Time LastTime ...
                 GetAllPriceLevels() / GetPriceVolumeInfo(Decimal)
PriceVolumeInfo: Volume / Bid / Ask / Between / Price / Ticks
RenderContext: DrawLine / DrawString / FillPolygon / FillRectangle / MeasureString
RenderPen: (Color) (Color,Single) (Color,DashStyle) (Color,Single,DashStyle)
Extensions.GetTimeFrameTypeChartPeriod(IChart) -> TimeSpan
DrawingLayouts: None / Historical / LatestBar / Final
```

选择说明：

- 用**两参数** `AddAlert`。另两个重载带 `Color`，该类型在两平台不同，两参数版可完全避开。
- 绘制层用 `DrawingLayouts.Final`，**不用 Historical** —— 沿用 CHANGELOG `-28` 的教训。
- 周期判定用 `GetTimeFrameTypeChartPeriod()` 返回的 `TimeSpan`，**不解析** `ChartInfo.TimeFrame` 字符串（`AtasBridge.cs` 已记录该格式不可靠）。

### 2.2 音效文件名不带扩展名（-4 的核心发现）

`AddAlert("alert1.wav", ...)` **既不抛异常也不出声**。线索来自 Sea 截图里另一个
指标（5F 的 Absorption）的「警报文件」下拉框：里面全是**不带后缀**的名字
（`xishouAbs` / `geiger` / `tap`）。该下拉是枚举 `<install>\Sounds\*.wav` 后
**去掉扩展名**填充的，平台自己会补 `.wav` —— 传 `alert1.wav` 等于去找
`alert1.wav.wav`，找不到就静默失败。

现用裸名 `alert1` / `alert3` / `beep_2_1`（两平台 Sounds 目录均有），
并开放为三个设置项。

### 2.3 ATR 来源

- **ATR(M5)**：本指标自算真实波幅均值（周期常量 14）。
- **ATR(D1)**：从 M5 流按图表时区聚合成日桶后再算，不引入第二数据序列。日桶
  不足时回退 `ATR(M5) x 12`。
- 两个周期为内部常量，**不是设置项** —— 任务卡参数清单是穷举式的，不擅自增加。

### 2.4 无前视偏差

`ClosedStats(int evalBar, ...)` 的取样上界硬编码为 `evalBar - 1`，只用被评估
K **之前**已收盘的 K。见 §5.1 的更正：初版这里写的是 `CurrentBar - 1`，是错的。

### 2.5 强制去重

- 阶段去重键 `(poolId, direction, barIndex)`
- 声音去重键 `(poolId, direction, barIndex, eventType)`，**先查集合再调 `AddAlert`**
- 重触发上限：仅「超时未收回」允许 1 次，其余置 `Swept` 永不再触发

### 2.6 无裸 catch

全文 `catch` 全部为 `catch (Exception ex)` 并记录类型与消息；无 `catch {}`。
`SafeCandle()` 返回可空并由调用方判空，缺一根 K 不会让指标崩掉。

## 四、回测结果（2026-07-16 → 2026-08-13，约 28 天 M5）

**统计在指标加载时即完成**（历史遍历中计算，用同一套「只读已收盘K」的逻辑），
不需要跑回放。回放只用于听声音、验证去重、观察两阶段流程。要更多样本直接拉长
图表历史即可。

全图累计：**确认 31 个 / 作废 157 个**（作废率 83%）。

| | 已结 | 触及TP1 | 到达TP2 | 止损 | 期望 | 平均最大浮盈 | 亏损单最大浮盈 |
|---|---|---|---|---|---|---|---|
| **做多** | 17 | 47%(8) | **41%(7)** | 59%(10) | **+0.49R** | 1.5R | **0.5R** |
| **做空** | 14 | 36%(5) | **21%(3)** | 79%(11) | **−0.13R** | 1.4R | **0.8R** |

组合期望 `(17×0.49 + 14×(−0.13)) / 31 ≈ **+0.21R/笔**`，**整体正期望**。

### 4.1 TP2 距离上限的效果

上一轮（`-6`，无上限）与本轮（`v2026.08.13-1`，上限 5R）对比：

| | 到达TP2 | 期望 |
|---|---|---|
| 做空（无上限） | 6%(1/18) | −0.81R |
| 做空（上限 5R） | **21%(3/14)** | **−0.13R** |

无上限时出现过 `盈亏比 11.1` 的信号 —— `NearestUsableOppositePool()` 取"最近的
且够 MinRR 的池"却没有上限，选中了 11R 之外的池，该笔触 TP1 后止损。

### 4.2 最重要的一条读数：亏损单的最大浮盈只有 0.5R / 0.8R

**亏损单几乎不往有利方向走，直接奔止损。** 三条完整的结算日志：

```
到达TP2   最大浮盈=2.37R  最大浮亏=0.01R  用时=47根   ADR=0.28
直接止损  最大浮盈=0.10R  最大浮亏=1.31R  用时=6根    ADR=0.23
到达TP2   最大浮盈=4.02R  最大浮亏=0.90R  用时=105根  ADR=0.44
```

赢单最大浮亏 0.01R，输单最大浮盈 0.10R —— **对错分得非常开**。

结论：**离场计划不是瓶颈，把 TP1 拉近救不了**（输单连 0.5R 都到不了）。
失败的交易失败得干净利落，没有「到手利润吐回去」的消耗。真正的杠杆在
**提高胜率 = 收紧入场过滤**，而不是调目标位。

> 这一条更正了本报告作者在 `-6` 阶段给出的判读表：当时写的是
> 「亏损单平均最大浮盈 < 1.0R → 入场时机问题」，方向是对的，但同时给出的
> 「1.0~1.5R → 把 TP1 改成 1.0R」建议在本数据下不成立，因为输单根本走不到。

### 4.3 做空为什么差

做空 79% 止损、期望 −0.13R，仍弱于做多。两种可能未能区分：

1. 回放窗口内 BTC 整体处于宽幅震荡偏下行，空单多在反弹段被扫；
2. 逻辑本身对空头方向存在系统性劣势。

**14 笔样本太小，一个市场状态下的结果不足以定性。** 建议在明显上涨段与明显
震荡段各跑一次（直接拉长图表历史即可），看做空的负期望是否稳定复现。若只在
特定行情出现，那是行情问题而非逻辑问题。方向过滤属于新卡范围，9G 明确排除了
状态矩阵这类东西，本卡未做。

## 五、自我更正（初版报告与迭代中的错误结论）

### 5.1 「复盘与实盘一致」是错的

初版报告 §1.5 断言两阶段检测「历史计算时 `OnCalculate` 每根 bar 调一次且累计量
已是终值，等于该 bar 最后一个 tick 的状态，因此标记落在同样的 bar 上」。

**该结论被 Sea 的第一次回放证伪：3 天回放零信号、零日志。** 真实原因是两个 bug：

- **Bug A**：`if (bar == CurrentBar) RealtimeStageOne(CurrentBar);` —— 历史计算时
  ATAS 以 `bar = 0..N` 逐根回调而 `CurrentBar` 一开始就等于 N，该条件只在最后
  一次回调成立，**阶段一在整张图上只被评估了 1 根 K**。池照常构建（所以池线
  看起来完全正常），但没有任何池进入 WATCH。
- **Bug B**：`ClosedStats()` 的取样上界同样写的 `CurrentBar - 1`，历史计算时那
  就是整张图的最后一根 —— **分位数/中位数用了未来数据**，正是任务卡实现要求 3
  警告的前视偏差，且只在复盘暴露。

修法：一切以正在计算的 `bar` 为基准，不再引用 `CurrentBar`。

### 5.2 声音门控错了两次

- `-3`：`_historyDone && bar >= CurrentBar` —— 静音。
- `-4`：`bar >= CurrentBar` —— 仍静音。
- `-5`：诊断日志给出答案 `sound suppressed (not right edge) bar=54 CurrentBar=8539`
  —— **ATAS 市场回放时 `CurrentBar` 恒为整个已加载序列的末尾**（8539 根 M5 ≈ 30
  天），不是回放光标；且每个回放步都重算整个序列。门控改为跟踪本实例处理过的
  最大 bar，并新增「历史与回放也播声音」开关。

### 5.3 调小合并容差的建议方向是错的

`-5` 阶段建议 Sea 把「等高等低合并容差」调小以减少灰线。实测**灰线没减少**，
同一笔 63801 做多的盈亏比反而从 2.9 掉到 1.7。原因：容差调小 ⇒ 池更多更密 ⇒
「对面最近的池」离入场更近 ⇒ TP2 更近 ⇒ 盈亏比更低 ⇒ 标灰更多。

真因在 TP2 取法（照卡片字面取了最近的池），已改为「最近的、且距离足够达到
MinRR 的池」，一个都不合格时退回 3R。

### 5.4 中文方框不是 ATAS 或系统的问题

是字体写死成 `Arial`（无 CJK 字形），而 `OFT.Rendering` 的 `RenderFont`
**不做字体回退**。`AtasBridge` / `AtasLiquidations` 也用 Arial，但只画 ASCII，
所以从未暴露。ATAS 设置窗口中文正常，是那层 WPF UI 会回退，绘制层不会。

未做自动探测：`InstalledFontCollection` 在 ATAS X 能编过，但 Platform 直接
`CS0012: IPointer<> 在未引用的程序集 System.Private.Windows.Core 中定义`。
改为开放设置项「面板字体」，默认 `Microsoft YaHei UI` —— 该机是精简版
Windows IoT LTSC，仅 153 个字体，**有 `Microsoft YaHei UI` 但没有
`Microsoft YaHei` / `SimSun` / `SimHei`**，写死任何具体字体名都不安全。

## 六、其它偏差报备

### 6.1 ASCII 约定与 Sea 要求冲突

任务卡与 CHANGELOG v5.1 都要求源码纯 ASCII。Sea 后续明确要求参数中文化，
故采取折中：**UI 字符串中文、代码注释保持英文 ASCII**。v5.1 那条约定的真实
动因是「PowerShell 编码损坏中文注释」，针对的是注释与编辑方式，不是 UI 字符串
（`AtasLiquidations` 的 `DisplayName` 本来就是中文）。文件为 UTF-8 无 BOM，与
另两个源文件一致，文件头加了 ENCODING NOTE。

### 6.2 OKX 合约面值 / 量纲假设

`吸收最小量(BTC)` 直接与 `PriceVolumeInfo.Bid/Ask` 比较，即假设图表成交量口径
是 BTC。对 BTCUSDT@BinanceFutures 成立。挂到 OKX 永续（张）需要换算系数，
本卡范围内未做。

### 6.3 `ArmDistance` 在卡片正文无对应逻辑

参数清单有、两阶段描述里没有 ARMED 状态。按字面语义实现为**预筛**：只有价格
进入该距离内的池才参与阶段一判定。

### 6.4 超出卡片参数清单的新增设置项

`BSL颜色` / `SSL颜色`（卡片要求两色可区分，不可配置则无意义）、`面板字体`、
三个音效文件名、`历史与回放也播声音`、`显示线条文字`、`显示胜率统计`、
`TP2最大R`。每一项的动因都记在 CHANGELOG 对应版本里。

### 6.5 日志上限限制了离线分析

`LOG_MAX = 40` 是整个指标实例的日志总上限，预警/确认/作废会先把额度用掉，
导致 `结果` 行只落了 3 条。面板统计不受影响（它不依赖日志），但若要做逐笔
离线分析，需要提高该上限或让结果行独立计数。**已知限制，未修**。

| 做空 毛期望 | −0.13R | +0.10R | +0.17R |
| 分批毛期望（合计） | — | **+0.12R** | **+0.11R** |
| 成本 | — | ~0.31R（估） | **0.19R（实测）** |
| **分批净期望（合计）** | — | **~−0.19R** | **−0.08R** |

**28 天那组是噪声**：31 笔样本给出"做多 +0.49R、亏损全来自做空"，469 笔上完全
不成立，方向还反了过来。这是本卡最大的一次判断失误，教训是**小样本不要下方向性
结论**。

### B. 分批离场口径确实有效

`+0.05R -> +0.12R`（全进全出 -> TP1 减半仓 + 移保本），翻 2.4 倍。原因是
触及TP1 41~43% 而到达TP2 仅 26~28%，中间那 15.6% 的单子走到过 1.5R 却被
全进全出口径记成完整 −1R。

**离场纪律对这套 setup 的影响大于入场调参** —— 这条结论在两个样本上都成立。

### C. 交易成本才是决定性的

仓位 = 权益 × 风险% ÷ R，故 `成本(R) = 2 × 单边费率 × 入场价 ÷ R`，
只取决于**入场价与 R 的比值**。R 中位数 205 美元、价格 64000 时，仅币安 taker
手续费就是 0.28R，而毛边际只有 0.12R。

按建议把「最小止损距离」从 0.15% 提到 0.4% 后（筛掉小 R 信号）：

- 成本 **0.31R → 0.19R**，符合预测
- 毛边际 **+0.12R → +0.11R**，纹丝不动
- 净期望 **−0.19R → −0.08R**，改善但仍为负

### D. 这条路的天花板已经算出来了

成本 0.19R 反推 `入场价/R ≈ 190`（R ≈ 337 美元）。`最大止损距离` 上限 0.8%
对应 R ≈ 512 美元：

```
最理想：R = 512 -> 成本 = 2 × 0.05% × 64000 / 512 = 0.125R
                   净期望 = 0.11 − 0.125 ≈ −0.015R
```

**即便把信号全筛成最大 R，净期望也只是约等于零。** 继续提高「最小止损距离」
只会让样本更少、结论更不可靠。**毛边际 0.11R 本身就低于任何现实成本**，这是
根本约束，不是调参能解决的。

### E. 唯一有量级的杠杆：限价进场

```
市价进场（taker 0.045% + 滑点）  成本 0.19R  ->  净 −0.08R
限价进场（maker 0.018% + 微滑点）成本 0.076R ->  净 +0.034R
```

把 taker 换成 maker 使成本降约 60%，是唯一能让净期望转正的单一改动。做法是在
池位挂限价单等回踩，而非确认K收盘时市价追。代价是漏掉不回踩的信号 —— 但那些
往往是动能过强、后续继续突破的，漏掉未必是坏事。**需要改入场逻辑，属新卡范围，
9G 未做。**

### F. 测量口径提醒

「最小止损距离」提高后，`作废` 从 1822 涨到 2098，而确认从 469 降到 193 ——
不是 bug：被「止损过近」拒绝的 276 个信号进了作废计数（`RecordRejected()` 会递增
`_totalInvalidated`）。因此过滤后的作废率（2098/2291 = 92%）被过滤器抬高，
不能与过滤前直接比较。真正的"setup 失败率"需从作废中扣除这部分。

### G. 最终结论与建议

**不建议把 SweepMarker 当独立开仓系统使用**，三条理由：

1. 毛边际 0.11R 太薄，低于任何现实成本
2. 筛大 R 这条路的天花板已算出，就在打平附近
3. 469 -> 193 的样本收缩说明可用信号本就不多

**两个仍然成立的用法**：

- **改限价进场后重测**（新卡）—— 唯一可能翻正的路径，值得一试
- **当作择时辅助** —— 已有仓位时用其信号决定加减仓时点，不产生额外开仓成本，
  0.19R 的成本项不存在，+0.11R 的毛边际即为净收益

**关于方向**：做空在两次测量中均优于做多（469 样本 +0.16 vs +0.08；193 样本
+0.20 vs +0.04）。但 193 是 469 的子集，两者不独立，**只能算一个观察**，
不足以据此只做空。需在互不重叠的时间段上各测一次才能定性。

## H. M15 验证与成本恒等式（2026-08-13，本卡终局）

### H.1 M15 实测：两头都更差

365 天 M15、最小止损距离 0.15%（周期警告正常显示，验证 6 再次通过）：

```
全图累计：确认 185 个 / 作废 863 个
做多：已结 109 笔  到达TP2 28%(30)  止损 72%(79)  毛期望 +0.08R  成本 -0.24R  净期望 -0.16R
做空：已结  76 笔  到达TP2 22%(17)  止损 78%(59)  毛期望 -0.11R  成本 -0.23R  净期望 -0.35R
分批口径：做多 +0.15R  做空 -0.12R  合计 +0.04R  ||  扣成本后 合计 -0.20R
```

| | M5 基线 | M5 筛 0.4% | **M15 基线** |
|---|---|---|---|
| 确认信号 | 469 | 193 | 185 |
| 分批毛期望 | +0.12R | +0.11R | **+0.04R** |
| 成本 | ~0.31R | 0.19R | **0.24R** |
| 分批净期望 | ~−0.19R | −0.08R | **−0.20R** |

**「换到更高周期能降低成本占比」的假设被证伪**，而且 M15 的毛边际只有 M5 的
三分之一。M5 反而是这套 setup 更合适的周期。

### H.2 为什么换周期无效 —— 成本恒等式

成本 `= 2 × 费率 × 入场价 ÷ R`，而 `R = 止损距离% × 入场价`，入场价约掉：

```
成本(R) = 2 × 单边费率 ÷ 止损距离%
```

**成本只取决于止损距离占价格的百分比，与周期、与币价完全无关。**

反验：M15 成本 0.24R 反推平均止损 `2×0.05/0.24 = 0.42%`；M5 筛后成本 0.19R
反推 0.53%。M15 那次把最小止损设回了 0.15%，平均止损反而比筛过的 M5 更窄，
成本因此更高 —— 与周期无关。

按此公式成本完全可预测：

| 止损距离 | 成本 |
|---|---|
| 0.15% | 0.67R |
| 0.40% | 0.25R |
| 0.80%（`最大止损距离` 上限） | **0.125R ← 地板** |

**成本下限 0.125R，而毛边际最好 +0.11R。在 taker 费率下无论怎么调都到不了
正期望** —— 这是算出来的，不是试出来的。

### H.3 终局结论

作为独立开仓系统：**确认不可用**。可能性已被穷尽：

| 方向 | 结果 |
|---|---|
| 调参 | 天花板 −0.015R（§D 算出） |
| 换周期 | 无关变量，实测更差（H.1） |
| 筛大 R | 成本降但毛边际不动（§C） |
| 限价进场 | 可转正，但仅 +0.02~0.05R |

限价（maker 0.018% + 微滑点 ≈ 0.023%/单边）：止损 0.5% 时成本 0.092R → 净
+0.02R；止损 0.8% 时成本 0.058R → 净 +0.05R。能转正，但薄到不值得为它单独写
一套挂单与撤单逻辑，且要承担挂单不成交的漏单风险。

**唯一推荐的用法：择时辅助。** 已有仓位时用其信号决定加减仓时点 —— 不产生额外
开仓成本，成本项归零，`+0.11R` 的毛边际即为净收益。此用法无需任何代码改动。

### H.4 本卡真正的产出

指标实现本身是合格的（验证 1–6 全过）。但本卡最有价值的产出不是指标，而是
**用 469 笔样本 + 一个恒等式，证明了 Setup C 在 BTC 上的边际扛不住交易成本**。
若没做这一步，很可能拿着一个毛期望为正的系统去实盘，被手续费慢慢磨死。

成本恒等式 `成本(R) = 2 × 单边费率 ÷ 止损距离%` 值得记下来：**任何以固定 R 为
风险单位的策略，在动手写代码之前就能用它判断成本会吃掉多少边际。**
