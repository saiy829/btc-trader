选择说明：

- 用 **两参数** 的 `AddAlert(soundFile, message)`。另两个重载带 `Color`，而 `Color`
  在两平台是不同类型，用两参数版可以完全避开这个分歧。
- 绘制层用 `DrawingLayouts.Final`，**不用 Historical** —— 沿用 CHANGELOG `-28`

- 周期判定用 `GetTimeFrameTypeChartPeriod(ChartInfo)` 返回的 `TimeSpan`，
  **不解析** `ChartInfo.TimeFrame` 字符串 —— AtasBridge.cs 里已记录该字符串
  格式随图表类型变化、解析不可靠。

### 1.2 音效文件（实测存在）

两平台 `<install>\Sounds\` 下均确认存在：`alert1.wav`（预警）、`alert3.wav`（确认）、

文件名这一项。

### 1.3 ATR 来源

- **ATR(M5)**：本指标自算真实波幅（`max(H-L, |H-prevC|, |L-prevC|)`）的 N 期均值。
- **ATR(D1)**：从 M5 流按**图表时区**（`InstrumentInfo.TimeZone`）聚合成日桶后再算
  日真实波幅均值。这样不必为一条日线 ATR 去引入第二数据序列。日桶尚未攒够时
  回退到 `ATR(M5) x 12` 的估计值，使 `EqualTolerance` 在刚加载的图上仍然可用。
- 两个周期均为内部常量 14，**不是设置项**：任务卡的参数清单是穷举式的，两个
  ATR 周期不在其中，故不擅自增加设置项。

### 1.4 无前视偏差（任务卡实现要求 3）

`ClosedStats()` 的取样上界硬编码为 `CurrentBar - 1`：

```csharp
int last = CurrentBar - 1;            // never include the open bar
```

分位数与中位数只用已收盘 bar。把当前未收盘 bar 纳入统计会把结果泄漏进阈值，
是典型的前视偏差。

### 1.5 复盘与实盘一致（任务卡实现要求 4）

所有收盘处理走同一条路径，历史全量计算与实时 tick 都经由它：

```csharp
while (_lastClosedProcessed < CurrentBar - 1)
    ProcessClosedBar(++_lastClosedProcessed);
if (bar == CurrentBar) RealtimeStageOne(CurrentBar);
```

阶段一只读 (a) 当前 bar 的累计量、(b) 已收盘 bar 的统计量。历史计算时
`OnCalculate` 每根 bar 调一次且累计量已是终值，等于该 bar 最后一个 tick 的状态，
因此标记落在同样的 bar 上。另外 ADR 的分母（扫除 bar 的 |Delta|）在该 bar 收盘
的那一刻冻结（`SweepBarDeltaFinal`），避免实时值与复盘值不同。

### 1.6 强制去重（任务卡两处强调）

- 阶段去重键：`(poolId, direction, barIndex)` → `_dedup`
- 声音去重键：`(poolId, direction, barIndex, eventType)` → `_soundDedup`，
  且**先查集合再调 `AddAlert`**
- 重触发上限：作废原因为"超时未收回"时允许 1 次重触发（`RetriggerCount < 1`），
  其余原因一律置 `Swept` 永不再触发

### 1.7 显式状态机（任务卡实现要求 2）

每个池维护：`State(Active/Swept/Expired)`、`Stage(Idle/Watch)`、`Direction`（由
`Kind` 推出）、`SweepBarIndex`、`SweepExtremePrice`、`SweepBarDelta`、
`SweepBarDeltaFinal`、`SweepTimeUtc`、`RetriggerCount`、`Reclaimed`、
`PostSweepAbsDelta`。

### 1.8 无裸 catch（任务卡实现要求 1）

全文 12 个 `catch` 全部为 `catch (Exception ex)` 并记录类型与消息；无 `catch {}`、
无 `catch (Exception) {}`。`LogEx()` 统一输出 `EX at <where>: <Type>: <Message>`。
`SafeCandle()` 返回可空并由调用方判空，缺一根 K 线不会让指标崩掉。

## 三、遇到的问题

### 3.1 运行时验证需要重启 ATAS，未获授权（阻塞项）

指标要生效必须把新 dll 覆盖到 `%APPDATA%\ATAS X\Indicators\` 与
`%APPDATA%\ATAS\Indicators\`，且 ATAS 会锁定已加载的程序集 —— 必须关掉 ATAS 才能
覆盖，覆盖后还要重启才能加载新指标。当前 `OFT.Platform.exe` 与
`OFT.PlatformX.exe` 都在运行（本会话早前 Sea 已明确选择"先不动 ATAS"），因此
没有执行部署与验证 2~6。

准备就绪后执行（会自动覆盖指标目录，**执行前请先关闭 ATAS**）：

```bash
dotnet build C:\AtasBridge\AtasBridge.csproj -c Release
dotnet build C:\AtasBridge.Platform\AtasBridge.Platform.csproj -c Release
```

两条命令各自带 `CopyToATAS` / `CopyToATASPlatform` 目标，会把 dll 分别送到
`%APPDATA%\ATAS X\Indicators\` 和 `%APPDATA%\ATAS\Indicators\`。回滚办法是把
备份的旧 dll 拷回去；现网旧 dll 建议先手工备份一份。

### 3.2 任务卡与仓库约定的两处不一致

- **ASCII 约定**：任务卡要求"源码纯 ASCII，注释用英文"，CHANGELOG `v5.1` 也确立了
  这条（"新增代码注释使用英文（ASCII），避免历史上 PowerShell 编码损坏中文注释
  的问题"）。但 `AtasLiquidations.cs`（2026-08-09，晚于 v5.1）通篇是中文注释，
  且 `[DisplayName]`/`[Display(Name=...)]` 用的是中文。本卡按任务卡与 v5.1 的
  约定执行：`SweepMarker.cs` 纯 ASCII、设置项名称与描述全英文。代价是 ATAS 设置
  面板里 SweepMarker 的参数是英文、AtasLiquidations 是中文，视觉上不统一。
- **`#if` 分支**：任务卡要求"双平台：两个 csproj + `#if` 分支"。`AtasBridge.cs`
  实际上**没有** `#if` 分支（其注释说明双平台接口逐项一致因此不需要）。
  `SweepMarker.cs` 需要分支的地方只有一处：暴露给设置面板的颜色属性类型
  （`SeriesColor` 别名），与 `AtasLiquidations.cs` 同一手法。绘制调用用的
  `System.Drawing.Color` 两平台一致，不需要分支。

### 3.3 `ArmDistance` 在卡片正文中无对应逻辑

参数清单里有 `ArmDistance`（默认 0.5，"ARMED 触发距离"），但第二部分的两阶段
描述里没有 ARMED 状态。按字面语义实现为**预筛**：只有当价格进入
`ArmDistance x ATR(M5) + MaxPenetration x ATR(M5)` 范围内的池才参与阶段一判定，
远处的池直接跳过。这既符合参数名，也避免每个 tick 扫描全部池。

### 3.4 吸收判定的量纲假设

`AbsorptionMinBtc`（默认 5.0 BTC）直接与 `PriceVolumeInfo.Bid/Ask` 比较，即假设
图表成交量口径就是 BTC。对目标合约 BTCUSDT@BinanceFutures 成立。若将来挂到 OKX
永续（张为单位）需要引入换算系数 —— `AtasBridge.cs` 里已有
`OKX_CONTRACT_TO_BTC = 0.01` 这套逻辑可复用，但本卡范围内未做。

方向语义与既有代码对齐：`PriceVolumeInfo.Bid` 是在买价成交的量（卖方主动），
`Ask` 是在卖价成交的量（买方主动）。多头 setup 要求 `Bid/Ask >= AbsorptionRatio`，
与 `AtasBridge.cs` 的 `bid_absorb` 判定同一套口径（CHANGELOG v5.1）。

### 3.5 `Category` 归类

`AtasLiquidations` 用 `[Category("Crypto Metrics")]`（Coinglass 数据类），
`AtasBridge` 没有 `[Category]`。SweepMarker 是价格行为工具，归到
`Crypto Metrics` 会误导，故用 `[Category("Setups")]`。
