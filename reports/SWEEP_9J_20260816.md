## 一、为什么开这张卡

9G/9H/9I 三张卡，每一张的结论都建立在**面板上的 8 个汇总数字**之上。而这些数字是从截图里读出来的。

代码里 `Signal` 结构体一直记着每笔信号的完整档案：

```
Bar, IsLong, Entry, Stop, Tp1, Tp2, R, Rr, Adr, Weak, RrLow, PoolId,
State, HitTp1, ResolvedBar, MaxFavR, MaxAdvR, Align, Filtered,
LimitPrice, LimitFilled, LimitExpired, LimitEntry, LimitR, LimitState, ...
```

**2292 个信号 × 25 个字段，从头到尾没有导出过一次。**
`LOG_MAX = 40` 把 ATAS 日志窗口限死在 40 行，所以只能看汇总。

后果不是"分析不够细"，而是**三个具体的分析动作根本做不了**：

| 做不到 | 因此发生了什么 |
|---|---|
| 看分布 | `+0.17R` 是稳定小赢还是几笔暴赚拉起来的，至今不知道 |
| 核对标签 | 9H 的方向标签**一次都没有对照图表检查过** |
| 样本外切分 | 参数扫描只能在同一份数据上反复切片 → 9I §9.3 因此拒绝执行扫描 |

第 2 行是本卡的主目标。

### 9H 的结论可能归因错了

9H 测出方向过滤的排序在两次测量间翻转，我判定为**过拟合**。

但当时**没有检查另一个解释：标签本身是不是有效的**。
如果 `顺势/逆势/中性` 根本没捕捉到它声称捕捉的东西，那排序当然会翻转 ——
那不是过拟合，那是**用一把没校准的尺子量东西，然后认真解读读数**。

两个解释导向完全相反的行动：

- 真是过拟合 → 方向过滤这条路死了，别再碰
- 是标签坏了 → 方向过滤**从未被真正测试过**，得修好尺子重测

**在分清楚之前，9H 的结论不该被当成定论。**

## 二、三个具体嫌疑（读代码得出，尚未证实）

### 嫌疑 1：四个比较点可能在时间上不成序列 ⚠ 最可疑

`RecomputeBias()`（[SweepMarker.cs](AtasBridge/SweepMarker.cs)）：

```csharp
decimal h1 = _htfSwingHigh[^1].Price, h0 = _htfSwingHigh[^2].Price;
decimal l1 = _htfSwingLow[^1].Price,  l0 = _htfSwingLow[^2].Price;
if (h1 > h0 && l1 > l0) _htfBias = Bias.Bull;
```

**`_htfSwingHigh` 和 `_htfSwingLow` 是两个独立维护的列表。**
`ScanHtfPivots()` 各自 append，没有任何机制保证这四个点在时间上交替出现。

所以理论上可能出现：**两个摆动高点来自今天，两个摆动低点来自三天前**，
四个点凑在一起判出一个"上升结构"。而人眼看图时读的结构是最近的 H-L-H-L 序列。

这正是"标签测的不是我以为的东西"的典型形态。

### 嫌疑 2：标签几乎不发火 —— 78% 落在中性

9H 实测：`顺势 11 笔 / 逆势 13 笔 / 中性 83 笔`（共 107）。

**107 笔里只有 24 笔拿到了方向标签。**
`HH且HL` / `LH且LL` 的严格定义让绝大多数时间都判为中性。

9H 的排序翻转，完全可以只用 `n=11` 和 `n=13` 解释 —— 标准误 `1.5/√11 = 0.45R`，
两组差半个 R 都算不上信号。**这未必是过拟合，可能只是没有样本。**

### 嫌疑 3：结构判定滞后且更新稀疏

摆动点需要左右各 `n` 根确认（默认 3），60 分钟周期即**滞后 3 小时**。
这不是前视（方向是保守的，正确），但意味着：

- 信号被判定时，参照的结构最多可能是 3 小时前的
- `_htfBias` 只在**新摆动点确认时**才更新，两次更新之间可能隔很久

## 三、本卡做了什么

### 3.1 逐笔 CSV 导出

新增设置组 **「9 导出」**：

| 参数 | 默认 | 说明 |
|---|---|---|
| 导出逐笔CSV | 关 | 打开后历史计算走完即导出；切换会强制重算并重新导出 |
| CSV路径 | `C:\AtasBridge\sweep_trades.csv` | 整体覆盖，不追加；父目录自动创建 |

**42 列**，每笔确认信号一行：

```
idx, bar, time, dir, entry, stop, tp1, tp2, r, r_pct, rr, adr, weak, rr_low, pool_id,
state, hit_tp1, resolved_bar, bars_held, mfe_r, mae_r, align, filtered,
htf_bias, sw_h1, sw_h1_time, sw_h0, sw_h0_time, sw_l1, sw_l1_time, sw_l0, sw_l0_time,
limit_price, limit_invalid, limit_filled, limit_expired, limit_fill_bar,
limit_entry, limit_r, limit_rr, limit_state, limit_hit_tp1
```

其中 `sw_*` 八列是本卡的核心：**把 `RecomputeBias()` 判定这一笔时用的那四个点
（价格 + 时间）原样冻结下来**，直接对准嫌疑 1。

### 3.2 实现要点

| 要求 | 落实 |
|---|---|
| **不改变任何信号逻辑** | `RecomputeBias()` 仍只比较价格；摆动点只是多带了一个时间戳字段 |
| 快照而非事后回读 | 摆动点列表是滚动的（上限 8 条），dump 时早已被挤掉，必须在确认瞬间 `SnapshotHtf()` |
| 小数点不被区域设置破坏 | 全部走 `CultureInfo.InvariantCulture` —— 逗号做小数点的区域会直接把 CSV 撕碎 |
| CSV 内容全 ASCII | `align`/`state`/`bias` 写 `with/against/neutral`、`tp2/stop/open`，中文只留在面板 |
| 一次计算只写一次 | `_csvDumped` 在 `ResetAll()` 里重置（与声音闸门相反：那个必须**保留**） |
| 失败必须可见 | 面板加一行「逐笔导出：…」显示行数或异常，**静默失败会让下游拿着旧文件做分析** |
| 时间可对图 | `BarTime()` 套用 `InstrumentInfo.TimeZone`，与图表横轴一致 |

写入时机：`bar >= CurrentBar` 首次成立时 —— 此时所有**能结算的信号都已结算**。

## 四、验证步骤

### 4.1 导出

1. 365 天 M5 图表，参数与 9I 一致：**最小止损 0.5%、方向过滤 0、进场模式 0**
2. 打开 **「9 导出」→ 导出逐笔CSV**
3. 面板底部应出现：`逐笔导出：已导出 107 行 -> C:\AtasBridge\sweep_trades.csv`
4. **行数必须等于面板「确认」数（107）**，不等说明快照或写入有问题

### 4.2 自检：用 CSV 重算面板数字，必须逐位吻合

**这是任何新分析之前必须先过的一关。** 分批口径的规则是：

| 结局 | 分批毛收益 |
|---|---|
| `state=stop, hit_tp1=0` | −1R |
| `state=stop, hit_tp1=1` | +0.5 × 1.5R + 0.5 × 0 = **+0.75R**（移保本） |
| `state=tp2` | +0.5 × 1.5R + 0.5 × `rr` |
| `state=tp1_open` / `open` | 未结算，**排除出分母** |

按此对 CSV 求均值，应得到 **分批毛 +0.17R、已结 107 笔、到达TP2 31 笔**。

**对不上就说明 CSV 或我对口径的理解有一个是错的 —— 先修这个，别急着下结论。**

### 4.3 标签验证（本卡主目标）

| # | 检查 | 判据 |
|---|---|---|
| 1 | **时间序列一致性** | 四个 `sw_*_time` 是否 H/L 交替？统计"非交替"占比。占比高 → 嫌疑 1 成立 |
| 2 | **标签陈旧度** | `time − max(四个 sw 时间)` 的分布。中位数若达数小时，说明结构参照严重滞后 |
| 3 | **四点跨度** | `max(sw时间) − min(sw时间)`。跨度过大说明这四个点不构成一段可读的结构 |
| 4 | **人工核对** | 抽 20 笔（bull/bear/neutral 各若干），我给出时间点，**你对照图表判断标签对不对** |

第 4 项是唯一能真正定性的检查 —— 前三项只能证伪，不能证真。

### 4.4 顺带能做、但**不在本卡结论范围**

有了逐笔数据后，以下分析变得可能。**本卡只做上面的标签验证，这些留待后续卡**，
避免又一次"在同一份数据上反复切片找正数"：

- 收益分布（`+0.17R` 是否被少数几笔支配）
- 样本外切分 / walk-forward
- 9I 那 47 笔未成交信号的逐笔画像

## 五、结论口径（预先声明，防止事后挑数字）

本卡只回答一个问题：**9H 的方向标签测的是不是它声称测的东西？**

- **标签有效** → 9H 的"过拟合"结论成立，方向过滤这条路确实死了
- **标签无效** → 9H 结论作废，方向过滤**从未被测试过**；但**本卡不顺手重测**，
  修好尺子是下一张卡的事

9H 结论维持"，不去从四项检查里挑一个看着异常的当结论（9H §9.3 / 9I §9.3 的教训）。
