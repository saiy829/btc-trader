## 一、为什么开这张卡

9G 的终局结论是「作为独立开仓系统不可用」，理由是毛边际 +0.11R 低于成本地板
0.125R。但那个结论只穷尽了**成本侧**的四条路（调参 / 换周期 / 筛大 R / 限价
进场），**完全没有探索毛边际侧**。

Sea 在复盘一笔 M15 亏损单时问：「这个地方做多的原因是什么，指标是否考虑大的
时间框架」。这一问指向了 9G 最大的结构性空白。

### 1.1 那笔亏损单的完整还原

M15 图，2026-08-12 附近：

```
入场 63837　止损 63630.1　R=206.9　TP1 64147.4(1.5R)　TP2 64470(3.1R)　结果：已止损
```

触发链条逐条成立：SSL 池被击穿 → Delta 落在近 50 根最低 5% → 成交量 ≥ 中位数×3
→ 3 根内收盘收回池上方 → ADR ≤ 0.8 → 出现吸收 → 确认做多。

**指标没做错，它严格按规则执行了。** 问题在于：这是价格从 64470 一路崩下来之后
的第一次反弹，`TP2 = 64470` 恰恰是那根刚崩掉的高点 —— 这笔交易的盈利目标要求
价格把整段暴跌完整走回去。

**那不是扫止损，那是真突破。** 而 9G 的指标区分两者的唯一手段是「最大穿透」和
「ADR」，两个都是**局部的、单周期的**度量，看不到"大方向已经转空"这件事。

### 1.2 数据一直在暗示这件事

| 证据 | 含义 |
|---|---|
| 作废原因 **29/31 是「穿透过深」** | 绝大多数"扫除"其实是真突破，指标在反复接刀，靠深度阈值事后否掉 |
| 469 样本：做空 +0.16R > 做多 +0.08R | 那段行情偏弱，逆势的一边更差 |
| M15 样本：做多 +0.15R > 做空 −0.12R | 换个时间段方向优劣**翻转** |

**方向优劣随行情翻转 = 典型的「缺少方向过滤」特征。** 不是逻辑对某一边有偏见，
是它根本不知道大方向在哪。

### 1.3 需要多大改善才值得

成本地板 0.125R（对应 `最大止损距离` 上限 0.8%），当前毛边际 +0.11R。要让净期望
有意义，毛边际需达到约 **0.25R**。按当前平均盈亏比 2.95R 反推所需 TP2 命中率：

```
0.25 = p × 2.95 − (1 − p)    →    p ≈ 31.6%
```

当前 26~28%。**只要把 TP2 命中率提高 4~6 个百分点，这套东西就活了。**

砍掉"逆着大方向接刀"那一类信号，正是最可能做到这一点的过滤。

## 二、严格范围

### 做什么

**只做一件事：高周期方向判定 + 按方向给信号打标签 + 统计分组。**

### 不做什么（逐条）

- 不做评分分级（SweepScore）
- 不做池质量打分
- 不做状态矩阵、CVD 排列
- 不做其它 Setup（A/B）
- 不改入场/止损/TP 的计算逻辑
- 不改两阶段检测逻辑
- 不做限价进场（另卡）
- 不推 VPS、不落库、不联网、不自动下单

**一次只验证一个变量。** 9G 的教训：多个改动同时下去，分不清是哪个起的作用。

## 三、核心设计：测量优先，过滤可选

### 3.1 关键决策

**不把过滤做成「开了才能测」的开关**，而是：

1. **永远**计算高周期方向
2. **每笔信号**在确认时打上方向标签（顺势 / 逆势 / 中性）
3. **统计按标签分组显示**
4. 过滤开关**只控制画不画、响不响**，不影响统计

**收益**：加载一次即可同时读到三组的净期望，无需反复切换设置对比。这也避免了
9G 中反复出现的「改了参数不知道是哪个改动起的作用」。

### 3.2 高周期方向如何判定

复用指标已有的两套机制，不引入新概念：

- **聚合**：沿用 `ATR(D1)` 的做法，把图表 K 线按时间桶聚合成高周期 K 线
  （已有先例：`UpdateDailyAtr()` 按图表时区聚合日桶）
- **摆动点**：在聚合后的高周期 K 上跑与主逻辑**同一套**摆动点检测

方向判定（经典市场结构）：

| 条件 | 判定 |
|---|---|
| 最新摆动高 > 前一摆动高 **且** 最新摆动低 > 前一摆动低 | **多头结构**（HH + HL） |
| 最新摆动高 < 前一摆动高 **且** 最新摆动低 < 前一摆动低 | **空头结构**（LH + LL） |
| 其余（含数据不足） | **中性** |

信号标签：

- 做多信号 + 多头结构 = **顺势**
- 做多信号 + 空头结构 = **逆势**
- 做多信号 + 中性结构 = **中性**
- 做空信号镜像

### 3.3 无前视偏差（硬性要求）

- 只用**已收盘**的高周期 K 桶参与结构判定，当前正在形成的桶不参与
- 高周期摆动点需要其右侧 N 根高周期 K **全部收盘**后才确认
- 聚合在 `ProcessClosedBar()` 中按时间顺序增量构建，天然因果

## 四、参数清单（新增分组「7 高周期过滤」）

| 参数 | 默认 | 含义 |
|---|---|---|
| 高周期(分钟) | 60 | 用于判定方向的周期。60=H1，240=H4 |
| 高周期摆动点左右K数 | 3 | 在高周期 K 上判定摆动点，左右各需多少根 |
| 方向过滤模式 | 0 | 0=关闭（全画全响）1=只顺势 2=只逆势 |
| 中性时放行 | true | 高周期结构不明确时是否放行 |

**「只逆势」不是笔误** —— 它是对照组。如果逆势子集的净期望显著低于顺势，就直接
证实了假设；如果两者差不多，说明方向过滤这条路也不通，可以及早收手。

## 五、验证方式

**加载一次即可完成**（统计在历史遍历中算完，无需回放）：

1. 365 天 M5 图，`方向过滤模式 = 0`（关闭）
2. 读面板新增的三行分组统计：顺势 / 逆势 / 中性
3. 判定标准：

| 结果 | 结论 |
|---|---|
| 顺势子集毛边际 ≥ 0.25R | **假设成立**，9G 终局结论需改写；下一步做限价进场把成本再压低 |
| 顺势 明显 > 逆势 但未达 0.25R | 方向有用但不够，需叠加其它过滤（另卡） |
| 顺势 ≈ 逆势 | **假设不成立**，方向过滤无效，9G 结论维持，及早收手 |
